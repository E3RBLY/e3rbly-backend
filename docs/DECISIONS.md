# Decisions

| Date | Decision | Alternatives | Why |
|---|---|---|---|
| 2026-09-29 | Refactor incrementally, don't rebuild | Rewrite from scratch | Small codebase, sound structure; problems are ops/security, not design. |
| 2026-09-29 | Keep Cubit (`flutter_bloc`) + `get_it` in mobile | Migrate to Riverpod | Already used consistently in 20+ places; switching is churn with no user value. |
| 2026-09-29 | Rewrite backend git history to remove secrets (owner-approved) | Fresh repo; keep history + private | Keeps commit history while removing the files. PR refs need a GitHub Support purge. |
| 2026-09-29 | Branch model: task branches → PR → `develop` → one final PR → `main` | Trunk-based on `main` | Owner request: one branch per feature, push to `main` at the end. |
| 2026-09-29 | Docs live in the backend repo `docs/` (covers both apps) | Duplicate in both repos | One source of truth; the mobile README links to it. |
| 2026-09-29 | Gemini via REST + built-in fetch, no SDK | `@google/genai` SDK | Old SDK retired; npm unreachable from Claude's workspace; REST is small and stable. Revisit if we need streaming or tools. |
| 2026-09-29 | In-memory per-IP rate limiter | express-rate-limit; Upstash Redis | No new dependency (npm blocked) and no new vendor/cost (Tier C). Per-instance on Vercel; upgrade to a shared store if abuse is observed. |
| 2026-09-29 | AI failures keep HTTP 500 (not 502/503/504) | Precise gateway codes | Released app maps 500 to a friendly message; other 5xx show a raw code (M6). Revisit after the app update ships. |
| 2026-09-29 | Removed /auth/* and JWT (Q5 default) | Keep and fix | Unused by the app; they carried C4/H5. Firebase ID tokens are the only auth. |
| 2026-09-29 | Tashkeel v1 = Gemini with a hard letters-unchanged guard, user marks preserved, LRU cache | Open-source diacritizer models (e.g. hosted neural models); rule + lexicon | No new hosting/cost; ships now. Quality is measured with a DER benchmark (gold set) before promoting it in the app; a dedicated model stays an option if DER is poor. |
| 2026-09-29 | Quran text = Tanzil **Uthmani (full, Hafs 'an 'Asim), txt-2, v1.1**, stored byte-for-byte, `-text` in `.gitattributes` | Uthmani-min, simple/clean scripts, Al Quran Cloud | Only source with explicit, saved terms (`licenses/tanzil-terms.md`). Full Uthmani keeps all Quranic marks; simplified variants drop information and would be a change to the text. Nothing is normalized; search will use a separate copy later. |
| 2026-09-29 | `/v1/quran` built as isolated `modules/quran/` (own app factory, own tests), no edits to legacy logic; mounted via 2 lines in `server.js` (owner approved "implement everything") | Fold into legacy `src/routes` | Keeps the module movable when the clean-architecture skeleton lands. Turn off: delete the `mountQuran(app)` line in `server.js`. |
| 2026-09-29 | Basmala: keep Tanzil's `text` verbatim, add `text_ayah` + `basmala_prefixed` | Strip the basmala from stored data | Tanzil terms forbid changing the text; the split is computed, lossless and tested. Clients choose which to show. |
| 2026-09-29 | No surah names in the API yet | Type 114 names by hand | Names/revelation metadata come from a separate Tanzil file whose terms I have not read; hand-typing risks typos in a Quran-adjacent dataset. |
| 2026-09-29 | Quran text in the app uses the platform Arabic font (`QuranTextStyle`), not the UI font | Playpen Sans Arabic; bundle KFGQPC font | Playpen lacks some Uthmani marks (e.g. U+06DF) and is a casual face. No Quran font may be bundled before KFGQPC's written terms exist. **Not verified on a real device** (tests render with test fonts). Swap in one place when the font is licensed. |
| 2026-09-29 | Mobile Quran surah names are app-authored constants (114) | Backend endpoint | Backend serves no names yet (Tanzil metadata terms unread). Reviewer to check once; test pins count/uniqueness. |
| 2026-09-29 | Global `AppViewport`: 900px max content width, system text scale capped at 1.5 for legacy screens | Per-screen fixes only | Legacy screens use fixed-height layouts; the cap prevents breakage at extreme accessibility sizes. Quran reader has its own scale control up to 2.0. Turn off: remove `builder:` in `lib/e3rbly_app.dart`. |
| 2026-09-30 | Annotations are file packs validated at load; server refuses to start on an invalid pack; only `reviewed` is served | DB table; serve everything with a badge | Enforces the content rules in code (license file must exist, provenance, review). Adding a source is data, not code. Turn off: delete `data/annotations/*`. |
| 2026-09-30 | Ayah detail (tafsir/i'rab/simple) built with NO content shipped | Seed with AI-written text | No tafsir/i'rab source is licensed yet and unreviewed AI religious text must not reach users. UI shows an honest "not available yet". Content arrives via permissions (docs/licenses/permission-requests.md) + reviewer. |
| 2026-09-30 | Public production serves labelled, unreviewed AI drafts by default (`QURAN_INCLUDE_UNREVIEWED` defaults to on) | Off by default + env var on Vercel | Owner asked for the feature to be public in production now. Every item keeps `review_status: unreviewed` and the app shows a warning. Turn off instantly: set `QURAN_INCLUDE_UNREVIEWED=false`. |
